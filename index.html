「公文分文」流程｜用戶旅程地圖（As-Is 現況）

Primary Persona：王科長（科室主管・分文決策者）・依同理心地圖六面向推導・對應講義 P.20-22（現況旅程與四大痛點辨識）

STEP 0

分文規則（旅程中的分流判斷依據）

每件公文先過「類型判斷」這一關，再決定走哪一條派工路徑——這是整趟旅程的核心分岔。
TYPE 1

🧭 特定業務公文 → 專責承辦人

依事務分配表分文給該業務的專責承辦人（誰職掌、誰承辦）。

TYPE 2

♻️ 一般通用公文 → 輪分

不屬特定業務的通用公文，依序輪流派工（輪分序目前由主管以紙本與記憶維護）。

🌱 AI 機會點
批次摘要今日待分公文：主旨／案由／來文機關一覽，自動標記疑似急件與專案公文、爆量預警。
分文建議 Agent：讀取主旨＋附件（OCR），輸出案由摘要與關鍵詞，供類型判斷使用。
自動分類：先標示 TYPE 1／TYPE 2 屬性＋判斷依據＋信心度；界線模糊者標示「疑似跨域・建議人工確認」。
TYPE 1：對照事務分配表 RAG 知識庫推薦專責人（附前例出處）。TYPE 2：自動輪分引擎——系統維護輪分序＋請假跳過＋負載均攤。
動態調度建議：串接請假與負載資料，自動推薦備援人選＋理由；多重案由自動建議拆分方式。
一鍵採納建議＋自動草稿夾註；主管核定後才送出（Human Gate）；退文原因自動歸類，回饋修正分文 Skill。

STEP 4

系統思考：分文的惡性循環（增強迴路 R）

🔁 為什麼分文永遠這麼耗時？

分文耗時越長 → 主管越沒空整理「特定／一般分類清單＋輪分規則」 → 規則持續留在腦中與紙本（未外顯） → 每件公文仍須人工判斷＋翻表＋心算輪分序 → 更耗時、更容易分錯與跳錯位 →（回到起點，且人事一異動，迴路整個斷鏈）。

槓桿解：把隱性分文規則外顯為分文判斷 Skill（SKILL.md）＋事務分配表 RAG 知識庫＋自動輪分引擎，讓 Agent 產出帶依據的分文建議，主管只做核定（Human Gate）——打破「逐件靠人腦」的迴路結構。
下一步：進入「痛點 → Skill → PoC → RFP」核心主線（講義 P.23-39）。
